# PF302: Cache restore in a job that holds credentials

A step in a privileged job restores a cache. Caches are shared across runs of differing trust, so a cache written by a less trusted run (or a poisoned one) would run inside a job that holds credentials. This is how the Ultralytics release compromise worked.

## How to fix it

Remove caching from this job. Build in an unprivileged job instead (without cache restore if it feeds a privileged job).
