# PF131: Output not declared, or from a job that isn't a dependency

A value `{ output: job.name }` reads an output that the named job doesn't declare, or that comes from a job this one doesn't depend on (directly or through `needs:`). Such a reference would always be empty at run time.

## How to fix it

Declare the output on the producing job, set it from a step, and depend on that job:

```yaml
version:
  runner: ubuntu-24.04
  outputs: [tag]
  steps:
    - run: echo "tag=v$(cat VERSION)" >> "$GITHUB_OUTPUT"
publish:
  runner: ubuntu-24.04
  needs: [version]
  permissions: { contents: write }
  steps:
    - effect: release
      tag: { output: version.tag }
```

An action's outputs work too, when the action sets an output with that name. If several steps set it, the last one wins.

Outputs are always treated as untrusted (tainted) where they are read: in a `run:` step only through an `env:` variable named `T_*`, and in a privileged job only where effects check them (a release `tag` must be a valid tag name). A job whose output reaches a privileged job is a feeder, so it can't restore caches (PF305).
