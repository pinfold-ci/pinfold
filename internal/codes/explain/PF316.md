# PF316: Gated job runs for content the triggering user didn't write

A job behind the maintainer gate runs on a trigger whose activity types include ones where the user who triggered the run may not have written the content the job reads.

The gate checks the user who triggered the run. When a maintainer edits or deletes someone else's comment (for example to remove a spam `/label approved`), adds a label to someone else's issue, or reopens someone else's pull request, that maintainer triggers the run, and the job would act on the other person's text as if the maintainer had written it.

A gated job may only run for the one activity type where the triggering user is the author:

| Trigger | Required `types:` |
| --- | --- |
| `issue_comment`, `pull_request_review_comment`, `discussion_comment` | `[created]` |
| `discussion` | `[created]` |
| `issues`, `pull_request_target` | `[opened]` |
| `pull_request_review` | `[submitted]` |

`push`, `schedule` and `manual` carry no such content and aren't restricted.

The generated gate checks the same at run time: it passes only when the event's comment, review, issue, pull request or discussion is new and written by the triggering user. This error catches the mistake early.

## How to fix it

Limit the trigger to new content:

```yaml
on: { issue_comment: { types: [created] } }
```

If the job really must run when a maintainer labels someone else's issue, drop `maintainer: true` and don't let the issue's text choose what the job does.
