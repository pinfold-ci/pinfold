# PF316: Gated comment job runs for edits or deletions

A job behind the maintainer gate runs on a comment trigger (`issue_comment`, `pull_request_review_comment` or `discussion_comment`) without `types: [created]`. Without that, it also runs when a comment is edited or deleted.

The gate checks the user who triggered the run. When a maintainer edits or deletes someone else's comment (for example to remove a spam `/label approved`), that maintainer triggers the run, and the job would act on the other person's text as if the maintainer had written it.

The generated gate also refuses at run time anything but a new comment by the triggering user, so this error catches the mistake early.

## How to fix it

Limit the trigger to new comments:

```yaml
on: { issue_comment: { types: [created] } }
```
