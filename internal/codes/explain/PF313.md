# PF313: Step not allowed under pull_request_target or a review trigger

Workflows on `pull_request_target`, `pull_request_review` and `pull_request_review_comment` run in the context of a pull request while holding the base repository's permissions. On the two review events, the default checkout is the pull request's merge commit (`refs/pull/<N>/merge`), so it contains the PR author's files. A release, attestation, artifact or deployment built from that checkout would publish someone else's content under your project's name.

Pinfold therefore allows only the label and comment effects there (`add_labels`, `remove_labels`, `comment`), with conditions on PR metadata: no checkout, no scripts, no other actions or effects.

## How to fix it

Keep this workflow to labelling and commenting. Run releases from a trusted trigger (a tag push, or `workflow_dispatch`), and move builds of pull request code to a `pull_request` workflow (untrusted builds arrive in v0.2).
