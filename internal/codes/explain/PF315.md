# PF315: Feeder or privileged job on a runner that may not be fresh

Pinfold's trust zones rely on every job getting a fresh machine. GitHub-hosted runners do that. A persistent self-hosted runner doesn't: code from one job (a build dependency in a feeder, or a pull request in another workflow) can leave a process or a modified file behind and act inside the next job on that machine, including your release job and its OIDC token. GitHub's own documentation warns against persistent self-hosted runners for this reason.

This job holds credentials or feeds a job that does, and its `runner:` isn't a standard GitHub-hosted label, so Pinfold can't assume a fresh machine.

## How to fix it

Use a GitHub-hosted runner, e.g. `runner: ubuntu-24.04`.

If this runner really is a fresh machine for every job (a GitHub larger runner with a custom label, or an ephemeral or just-in-time self-hosted runner that takes one job and is destroyed), say so:

```yaml
runner: linux-large
ephemeral_runner: true
```

Pinfold then stamps that assertion in the generated file's header, so reviewers see what the guarantees rest on. Labels are compared exactly: `Ubuntu-Latest` isn't a GitHub-hosted label.
