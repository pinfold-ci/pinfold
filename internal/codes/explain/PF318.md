# PF318: OIDC job without an environment

A job requests an OIDC token (`permissions: { id-token: write }`) but has no `environment:`.

An OIDC token is a credential that an outside service trusts: PyPI trusted publishing, a cloud provider's role, a package registry. Without an environment, the service can only trust "any workflow in this repository", and the repository has no place to add protection rules (required reviewers, allowed branches or tags) in front of the token.

With an environment:

- the service's trust policy (for PyPI, the trusted publisher's *environment* field) can name it, so other workflows can't use the trust;
- the repository can protect it: required reviewers, and deployment branches or tags limited to your release tags.

## How to fix it

```yaml
publish:
  runner: ubuntu-24.04
  environment: pypi
  permissions: { id-token: write }
```

Then, in the repository settings, add protection rules to the environment, and enter the same environment name in the service's trusted publisher settings. `pinfold init` prints these steps.
