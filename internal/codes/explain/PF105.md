# PF105: Encoding or size limit

The spec isn't valid UTF-8, it's larger than 1 MiB, or it contains a Unicode line or paragraph separator (U+0085, U+2028 or U+2029). YAML reads those as line breaks, but many editors and diff views show them on one line, so they could hide a key from someone reviewing the spec.

## How to fix it

Save the file as UTF-8, and remove any Unicode line or paragraph separators (they're invisible in most editors; search for `\u2028`, `\u2029` and `\u0085`). A spec should never come close to 1 MiB; split very large configurations or open an issue.
