# PF307: Artifact download outside consumes:

This job either holds credentials or feeds a job that does, and it downloads an artifact with a hand-written `actions/download-artifact` step.

Pinfold only knows where an artifact comes from when you declare it with `consumes:`. Then it treats the producing job as a feeder (no cache restore, PF305) and checks the artifact's id and digest before downloading it. A hand-written download skips both checks. A cache-restoring job could then feed your release through it, which is how the Ultralytics release was poisoned.

## How to fix it

Make the producing job declare `produces: { <name>: <path> }`, and replace the download step with:

```yaml
consumes: { <name>: { from: <producing job>, to: <path> } }
```

Hand-written downloads are fine in jobs whose outputs no privileged job uses.
