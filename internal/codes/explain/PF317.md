# PF317: Branch condition on an event without a branch

A job's `if:` uses `branch:`, but the workflow also runs on an event that has no branch to match:

- `issue_comment`, `issues`, `discussion`, `discussion_comment` and `schedule` runs always use the default branch, so `branch: main` would be true for every comment, whichever pull request it is on.
- `pull_request_review` and `pull_request_review_comment` runs use the pull request's merge ref, so `branch:` would never match.

`branch:` is meaningful only for `push` (the pushed branch), `pull_request_target` (the pull request's base branch) and `manual` (the branch chosen for the run). A tag with the same name as the branch never matches.

## How to fix it

Put the branch-dependent job in its own workflow on `push`, `pull_request_target` or `manual`, or filter with the trigger's `branches:` key instead:

```yaml
on: { push: { branches: [main] } }
```
