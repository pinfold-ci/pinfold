# PF322: actor: condition on a job that holds credentials

A privileged job (one that holds credentials or runs under a privileged trigger) uses `actor:` in its `if:`.

`actor:` only compares the login name of the user who started the run. It doesn't check that this user still has access to the repository, and logins can be renamed: once a maintainer renames their account, anyone can register the old name and pass the check. It also says nothing about *what* the user did; on comment events it is weaker than the gate's "new comment by the triggering user" rule.

The maintainer gate (`maintainer: true`) asks GitHub for the triggering user's current role on the repository, fails closed, and skips the job neutrally for everyone else.

## How to fix it

```yaml
if: { all: [ { maintainer: true } ] }
```

To allow a custom repository role as well:

```yaml
if: { all: [ { maintainer: { custom_roles: [release-manager] } } ] }
```

`actor:` is fine on unprivileged jobs, for example to skip a bot's pushes.
