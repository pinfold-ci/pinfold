# PF205: Event data chooses a release or status without the maintainer gate

This workflow runs on an event that people outside your project can cause, such as an issue comment. A `release` effect takes its `tag`, or a `commit_status` effect takes its `sha`, from that event's data, and the job doesn't require a maintainer.

Anyone who can comment could then create tags and releases in your repository, or mark any commit as passing a status check, including a check your branch protection requires.

## How to fix it

Require a maintainer for the job:

```yaml
if:
  all:
    - { comment: { starts_with: "/release " } }
    - { maintainer: true }
```

Or write the value out (`tag: v1.2.3`), or run the release from a trusted trigger such as a tag push (`tag: { context: ref.name }`).
